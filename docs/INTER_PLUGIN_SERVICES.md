# Безопасная шина межплагинных сервисов (RPC / Proxy Bridge) и зависимости плагинов

Архитектурное руководство по расширению возможностей плагинов через защищенную шину ядра Config Studio.

---

## 1. Декларация зависимостей (`dependencies` и `optionalDependencies`)

Плагины в Config Studio делятся на три категории:
1. **Автономные плагины (Zero-Dependency)** — не имеют внешних зависимостей.
2. **Зависимые плагины (Hard Dependencies, `dependencies`)** — требуют обязательного наличия и включения зависимого плагина.
3. **Плагины с мягкими зависимостями (Soft / Optional Dependencies, `optionalDependencies`)** — плагин полноценно работает самостоятельно, но получает дополнительные возможности («суперсилы»), если указанные расширения установлены и включены.

### Пример манифеста `plugin.json`:
```json
{
  "id": "quick-deploy",
  "name": "Quick Deployer",
  "version": "1.0.0",
  "dependencies": {
    "core-utils": ">=1.0.0"
  },
  "optionalDependencies": {
    "ssh-client": ">=1.0.0",
    "terminal": "*"
  },
  "permissions": [
    "service:ssh",
    "service:terminal"
  ]
}
```

### Сравнение жестких и мягких зависимостей:
| Свойство | `dependencies` (Обязательные) | `optionalDependencies` (Опциональные) |
|---|---|---|
| **Установка плагина** | Блокируется/предупреждает, если плагин отсутствует | **Разрешена всегда**, плагин работает без них |
| **Установка в 1 клик** | Пользователь должен найти зависимость | **Consent Dialog предлагает установить их вместе в 1 клик** |
| **Cascade Protection** | Нельзя отключить/удалить провайдера | **Провайдера можно свободно отключать и удалять** |
| **Порядок загрузки (DAG)** | Провайдер всегда инициализируется раньше | Если провайдер активен — инициализируется раньше |
| **Доступ к сервисам** | `services.get(name, consumerId)` | `services.getOptional(name, consumerId)` или `services.get` |

### Правила проверки версий:
1. **Отсутствие поля или пустой объект (`"dependencies": {}`)**:
   Плагин полностью автономен (Zero-Dependency). Никаких проверок зависимостей не производится.
2. **Пустая строка (`""`), звездочка (`"*"`) или `"latest"`**:
   Подходит **любая установленная версия** плагина (Any Version).
3. **Операторы версий SemVer**:
   - `">=1.0.0"` — версия 1.0.0 или новее.
   - `"<=2.0.0"` — версия до 2.0.0 включительно.
   - `"^1.2.0"` — совместимо в пределах мажорного релиза 1.x.
   - `"~1.2.0"` — совместимо в пределах минорного релиза 1.2.x.
   - `"1.0.0"` — строгое совпадение версии.

## 2. Защита от каскадных сбоев (Cascade Protection)

Если плагин `B` зависит от плагина `A`:
* **Запрет на отключение**: при попытке отключить плагин `A` ядро блокирует операцию и возвращает предупреждение:
  > *«Нельзя отключить "SSH Client". От него зависят активные плагины: Quick Deployer. Сначала отключите зависимые плагины.»*
* **Запрет на удаление**: плагин `A` невозможно случайно удалить, пока активны зависимые плагины.
* **Топологический порядок загрузки (DAG)**: ядро гарантирует, что провайдер `A` загружается и регистрирует свои сервисы **раньше**, чем начинает выполняться потребитель `B`.

## 3. Регистрация сервиса провайдером (`providesServices`)

### Шаг 1: Объявление в `plugin.json`
```json
{
  "id": "ssh-client",
  "name": "SSH Client",
  "version": "1.0.0",
  "providesServices": ["ssh"]
}
```

### Шаг 2: Регистрация в `main.js`
```javascript
window.ConfigStudio.services.register('ssh', {
  exec: async (host, cmd) => {
    return { stdout: `Executed on ${host}: ${cmd}`, exitCode: 0 };
  },
  ping: async (host) => {
    return { alive: true, latencyMs: 14 };
  }
}, 'ssh-client');
```

## 4. Безопасный вызов сервиса потребителем

### Шаг 1: Запрос разрешения в `plugin.json`
Потребитель обязан задекларировать разрешение `service:<имя_сервиса>`:
```json
{
  "id": "quick-deploy",
  "dependencies": {
    "ssh-client": ">=1.0.0"
  },
  "permissions": [
    "service:ssh"
  ]
}
```
*На экране подтверждения установки (Consent Dialog) пользователь видит понятное предупреждение: «Межплагинный сервис: ssh — Вызовы API методов сервиса ssh, предоставляемого зависимым плагином».*

### Шаг 2: Вызов в `main.js` через защитный Proxy Bridge

Для обязательных зависимостей:
```javascript
const ssh = await window.ConfigStudio.services.get('ssh', 'quick-deploy');
const res = await ssh.exec('192.168.1.10', 'docker ps');
console.log(res.stdout);
```

Для опциональных зависимостей (метод `services.getOptional` возвращает `null`, если провайдер не активен, не выбрасывая исключений):
```javascript
// Проверка наличия опционального сервиса и вызов
const ssh = await window.ConfigStudio.services.getOptional('ssh', 'quick-deploy');
if (ssh) {
  // Добавляем действие в тулбар или кнопку удаленного деплоя
  const res = await ssh.exec('192.168.1.10', 'docker ps');
  console.log(res.stdout);
} else {
  // Автономный режим работы: локальное выполнение или инструкция
  console.log('SSH-клиент не установлен, используем локальный режим');
}
```

### Гарантии безопасности Proxy Bridge ядра:
1. **Валидация зависимостей**: ядро блокирует вызов, если плагин не задекларировал провайдера в `dependencies` или `optionalDependencies`.
2. **Проверка прав**: ядро блокирует вызов, если плагин не запросил разрешение `service:<name>` в `permissions`.
3. **Изолирующий Proxy**: вызовы оборачиваются в защитную оболочку `Proxy`, предотвращающую падение интерфейса и перехватывающую ошибки.
4. **Автоматическая очистка**: при отключении или удалении плагина-провайдера все его сервисы автоматически разрегистрируются.
